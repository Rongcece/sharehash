# 五类哈希单线程评测结果

评测已执行完毕：5 类哈希 × 3 个数据规模 × 3 次重复，共 45 次独立进程运行；27 次通过插入返回成功数及查询命中数检查。哈希源码、参数、原有初始化与操作顺序保持不变，仅新增测量、返回值计数和 CSV 保存。

## 运行配置

- 数据规模：100,000 / 1,000,000 / 5,000,000；每类每规模重复 3 次，以下为中位数。
- 单线程：`-p 1`，绑定 CPU 0；`OMP_NUM_THREADS=1`、`OMP_DYNAMIC=FALSE`。
- 每次重复使用种子 20261025 / 20261026 / 20261027；相同规模及重复的五类哈希使用相同数据。
- 随机 uint64 键值对，键等于值，每条有效载荷 16 bytes；没有去重，BPK 分母为请求插入条数。
- CPU：Intel(R) Xeon(R) Gold 5320 CPU @ 2.20GHz；glibc：2.31。
- 保留原编译选项 `-pg -g -O1`，关闭 ASan/TSan；不能直接与其他优化选项下的吞吐量混比。
- 测量运行时间：2026-10-25 22:10:33 至 2026-10-25 22:11:26（北京时间，UTC+8）。
- `run_manifest.json` 保存命令、退出码、日志路径、检查结果、编译参数及源码/二进制/CSV 校验和。

## 失败运行与原实现问题

- ShareHash：9/9 次进程完成且插入均返回成功，但查询命中数低于请求条数。下面列出每个种子的实际命中数；未对返回值内容做校验。

| 条数 | seed=20261025 命中数 | seed=20261026 命中数 | seed=20261027 命中数 |
|---:|---:|---:|---:|
| 100,000 | 99025 | 99908 | 98896 |
| 1,000,000 | 998239 | 998187 | 998306 |
| 5,000,000 | 4980133 | 4998486 | 4998535 |

- MapEmbed：9/9 次收到 SIGABRT（Python return code -6），stderr 均为 `stack smashing detected`。10 万与 100 万的 6 次在完成插入、保存内存快照后退出；500 万的 3 次未完成插入。

源码检查发现以下现存问题，相关源码本次均未修改：

- MapEmbed 的 [murmur.h](../../benchmark/competitors/MapEmbed/src/murmur.h) 第 152–155 行写出 16 bytes，但 [MapEmbed.h](../../benchmark/competitors/MapEmbed/src/MapEmbed.h) 第 119/126 行仅提供 8-byte 缓冲，第 137/145 行仅提供 4-byte 缓冲，存在栈越界写。未定义行为的报错时机可能随插桩和编译改变。
- ShareHash 的 [ShareHash.h](../../include/ShareHash.h) 驱逐路径（约 303–340 行）可能把键移到其查询桶范围之外；扩容重插入路径（约 556–566 行）也会向其他桶放置键，而 `get()` 只查本桶。它们与实测漏查相符；未修改或修复这些路径。
- 原实现 MapEmbed 对象内还有未使用的 480,000,160-byte KV 数组，原始/分配器统计包含该预留；未触碰的部分不会完整进入 RSS，因此约 701 MB 的分配量与约 221 MB 的 RSS 可以同时成立。
